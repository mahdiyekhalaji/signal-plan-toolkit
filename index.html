Why the cycle is not a single answer

Two-way progression efficiency across the corridor (left axis) against cycle length, with intersection control delay on the right axis. Delay is a smooth U: short cycles fail on capacity, long cycles waste green, and that curve is stable. Efficiency is not, and the shaded band is why: the offset search is heuristic, and three runs at the same cycle can differ by ten points. What survives that spread is the pattern rather than any single peak. Bandwidth depends on whether half the cycle matches the travel time between signals, so the best cycle for the intersection and the best cycle for the corridor are not the same one.

What this is not

Read before using any number here.

Splits come from a two-phase Webster estimate. Real phasing at these signals almost certainly includes protected lefts, which adds lost time and lengthens the cycle.

Saturation flow is a flat 1800 vehicles per hour per lane. The full set of HCM adjustment factors exists in the repository but is not wired into this calculation.

Lane counts come from OpenStreetMap where tagged and from assumption where not. Nothing here has been checked against aerial imagery or survey.

Offsets are optimized for through bandwidth alone. Queue clearance, side-street delay and transit priority are not considered.

No timing sheet from the operating agency was used. Yonge at Steeles is a boundary signal run jointly with York Region.

Nothing here is a design. It is a first pass that shows where a corridor is worth studying properly.
